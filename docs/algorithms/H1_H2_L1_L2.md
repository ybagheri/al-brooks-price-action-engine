# H1/H2 and L1/L2 Pullbacks

## 1. Lifecycle

The specification requires four states to be distinguishable. A pullback is not
a single event, and collapsing it into a boolean discards most of what a trader
watches for.

```text
NONE  ->  CANDIDATE  ->  PROVISIONAL  ->  CONFIRMED
                  \->  INVALIDATED   (from any non-terminal state)
```

| State | Meaning |
|---|---|
| `NONE` | No pullback, or no trend to pull back in. |
| `CANDIDATE` | The pullback window is open and spans a meaningful range, but no counter-trend leg has completed. `legs == 0`. |
| `PROVISIONAL` | One counter-trend leg completed (H1 / L1), **or** two legs have formed but the trend has not resumed. |
| `CONFIRMED` | Two counter-trend legs formed and the trend resumed. `signal_bar` is set. |
| `INVALIDATED` | A later bar closed beyond the extreme the pullback depended on. |

## 2. Counting rules

Context gate first: `determine_trend_direction` requires a normalised
EMA20/EMA50 gap beyond `0.4 * ATR`. **Without a trend there is nothing to pull
back in**, and no setup is reported regardless of the bar pattern.

Then, over the window `[idx - max_pb_bars, idx]`:

1. The window must span at least `min_pb_ratio * ATR`. A smaller span is noise.
2. **Leg 1** (`H1`/`L1`): the first bar that extends further in the
   counter-trend direction, i.e. a higher high for a bull pullback.
3. **Counter-move**: the first bar after leg 1 that goes deeper than the level
   reached between the window start and leg 1.
4. **Leg 2** (`H2`/`L2`): the first bar after that counter-move that extends
   counter-trend again, **followed by** a bar that extends in the trend
   direction. That resumption bar is the `signal_bar`.

## 3. The bug this replaces

The previous implementation returned `setup_type="H1", legs=1` when a second
counter leg had formed but the trend had not yet resumed. That understates the
structure: two legs exist, so the pattern is an `H2` in progress, not a
completed `H1`. The lifecycle now reports `setup_type="H2", legs=2` with
`state=PROVISIONAL` and `signal_bar=-1`.

The distinction matters because a caller waiting for `CONFIRMED` should not
act on a partially formed H2, and a caller counting legs should not be told
there is only one.

## 4. Invalidation

Each setup records the `extreme_bar` / `extreme_price` it depends on -- the low
for a bull pullback, the high for a bear pullback. Once a **later** bar closes
beyond that extreme, the structure the pullback relied on no longer holds:

```text
bull: close < extreme_price  ->  INVALIDATED
bear: close > extreme_price  ->  INVALIDATED
```

`apply_invalidation` returns a copy marked `INVALIDATED` while preserving the
rest of the record, so a caller can still log what the setup had been.
Invalidation is evaluated at bars *after* the extreme; it is ignored at or
before it.

## 5. What this does not claim

- **`CONFIRMED` is not "more likely to work" than `PROVISIONAL`.** That ordering
  is a hypothesis for out-of-sample testing, not something this engine
  measures. `state` describes the structure, it does not rate it.
- No win rate, expectancy, or statistical property is claimed for any state.
- The `0.4 * ATR` context gate and the `0.15` minimum span are `HEURISTIC`
  values chosen by this project.
- The counting is `ALGORITHMIC` given the context, but the context itself is a
  `PROXY` (see [MARKET_CONTEXT.md](MARKET_CONTEXT.md)).

## 6. Implementation note

`detect_h1_h2` and `detect_l1_l2` were near-verbatim mirror images of each
other, which meant a correction could land in one direction and miss the other.
They now share a single `_classify` implementation with the sign flipped, so the
two directions cannot drift apart. The three pre-existing Phase 6 tests pass
unchanged, which is the evidence that the refactor did not alter the counting.

## 7. Configuration

| Key | Default | Meaning |
|---|---|---|
| `min_pb_ratio` | `0.15` | Minimum pullback span, in ATR |
| `max_pb_ratio` | `0.90` | Maximum pullback depth, in ATR |
| `max_pb_bars` | `50` | Pullback window length |
| `atr_period` | `14` | ATR used for all ratios |
