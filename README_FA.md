# موتور تحلیل پرایس‌اکشن ال بروکس

یک موتور تحلیل پرایس‌اکشن **مستقل از پلتفرم**، قابل توسعه و با کیفیت تولیدی،
نوشته‌شده به زبان پایتون.

> **English: [README.md](README.md)**

## هدف

این کتابخانه میله‌های بسته‌شده (closed OHLCV) را به تحلیل ساختاریافته و قابل
توضیح تبدیل می‌کند: وضعیت بازار، سقف‌ها و کف‌ها و پاها (swings/legs)،
حرکت‌های اندازه‌گیری‌شده (Measured Move)، تشخیص ستاپ‌ها، هندسهٔ برنامهٔ
معاملاتی (trade plan)، یک تصمیم، و خوانش تایم‌فریم بالاتر که تصمیم با آن سنجیده
می‌شود.

این یک **موتور تحلیلی** است، نه یک سیستم معاملاتی. هرگز سفارش ثبت نمی‌کند و
هرگز به متاتریدر ۵ وابسته نیست. یکپارچه‌سازی با پلتفرم‌ها فقط در لایه
adapter انجام می‌شود.

> ⚠️ **وضعیت کار:** از ۲۴ فاز (۰ تا ۲۳)، **۲۰ فاز کامل و تست‌شده است** (فاز ۰ تا ۱۹).
> فاز ۲۰ تا ۲۳ باقی مانده‌اند و هر چهار فاز کارِ پلتفرمی‌اند نه تحلیلی.
> وضعیت دقیق را در [ROADMAP.md](ROADMAP.md) ببینید.

| حوزه | وضعیت |
|---|---|
| ویژگی‌های میله‌به‌میله | پیاده‌سازی و تست واحد |
| سقف/کف، پاها، پیوت‌ها | پیاده‌سازی شده |
| بافت بازار | پیاده‌سازی شده |
| ساختارهای پرایس‌اکشن | پیاده‌سازی شده |
| H1/H2، L1/L2 | پیاده‌سازی شده، با حالت‌های چرخهٔ حیات |
| سقف/کف دوقلو، شکست، بازگشت روند | پیاده‌سازی شده |
| حرکت اندازه‌گیری‌شده | پیاده‌سازی شده، با شواهد و اطمینان |
| فید حرکت اندازه‌گیری‌شده | پیاده‌سازی شده — چرخهٔ حیات کامل |
| پایپ‌لاین `Analyzer.analyze()` | وصل شده — همهٔ لایه‌های بالا، فقط میلهٔ بسته |
| مدل شواهد | پیاده‌سازی شده — یک شکل فاکتور، امتیاز متعادل‌شده بر حسب منبع |
| برنامه‌های معاملاتی | پیاده‌سازی شده — ورود / حد ضرر / هدف، هر سطح با مبنای اعلام‌شده |
| تصمیم‌ها | پیاده‌سازی شده — رتبه‌بندی‌شده، فیلترشده و قابل توضیح |
| چند تایم‌فریم | پیاده‌سازی شده — هم‌ترازی میلهٔ بسته، سوگیری HTF به‌عنی وتو |
| قرارداد عدم بازترسیم | رسمی‌شده — ۱۸ تضمین شماره‌گذاری‌شده، هرکدام با نام تستش |
| بک‌تست | پیاده‌سازی شده — MFE/MAE، زمان تا سطح، نوع نتیجه. **بدون سود و زیان، عمداً** |
| فیکسچرهای طلایی | پیاده‌سازی شده — ۵ نمودار دست‌نویس، انتظار استخراج‌شدهٔ دستی، مثبت‌های نقض |
| پاریتی MQL5 | **شروع نشده** — فاز ۲۰ |
| آداپتور MT5 و لایهٔ MQL5 | **شروع نشده** — فاز ۲۱ |
| رابط AI / LLM | **شروع نشده** — فاز ۲۲ |
| مستندات دوزبانه | **ناقص** — فاز ۲۳ |

**وضعیت پیاده‌سازی اعتبارسنجی معاملاتی نیست.** در این پروژه هیچ ادعای عملکردی
مطرح نشده است. دو ردیف آخر (`بک‌تست` و `فیکسچرهای طلایی`) بیش از همه در معرض بدفهمی
به‌عنوان شاهد هستند و **شاهد نیستند**.

## معماری

```text
داده خام بازار
       ↓
نرمال‌سازی میله‌ها
       ↓
ویژگی‌های پایه پرایس‌اکشن
       ↓
سقف/کف و پاها و ساختار
       ↓
بافت بازار (Market State)
       ↓
تشخیص الگو
       ↓
تشخیص ستاپ
       ↓
ارزیابی ستاپ
       ↓
برنامه معاملاتی
       ↓
تصمیم / تفسیر
       ↓
آداپتور پلتفرم
```

وابستگی‌ها **فقط یک‌طرفه** به سمت پایین است. Measured Move هرگز به
Fading وابسته نیست؛ برعکس، Fading از Measured Move استفاده می‌کند. هسته
(core) هرگز MT5 را import نمی‌کند.

## شروع سریع

```python
from albrooks import Analyzer, AnalyzerConfig

config = AnalyzerConfig(atr_period=14, swing_k=3)
analyzer = Analyzer(config)

bars = [
    {"o": 100.0, "h": 101.0, "l": 99.0, "c": 100.5},
    # ... قدیمی‌ترین میله اول ...
]

result = analyzer.analyze(bars, symbol="EURUSD", timeframe="H1")

print(result.market_state["mode"], result.market_state["direction"])
for setup in result.setups:
    print(setup["detector"], setup["setup_family"],
          setup.get("setup_type") or setup.get("state"))

# تحلیل تا میله شماره ۹۹؛ میله‌های بعدی نتیجه را تغییر نمی‌دهند
snapshot = analyzer.analyze(bars, last_closed=99)
```

با پارامتر `last_closed` می‌توان تحلیل را **تا** یک میله مشخص انجام داد. همه
اطلاعات استخراج‌شده فقط از میله‌های `0..last_closed` خوانده می‌شود، بنابراین
نتیجه برای یک اندیس مستقل از وجود میله‌های بعدی یکسان است. مقداری که از انتهای
داده بگذرد بریده (clamp) می‌شود و خطا نمی‌دهد.

ورودی نامعتبر پنهان نمی‌شود. سری بدون میله، یا سری بدون نوسان، نتیجه‌ای برمی‌گرداند
که `market_state.reason` و `decision.reason` آن علت را توضیح می‌دهند و همه لایه‌ها
به‌عنوان «اجرا نشده» علامت می‌خورند — در غیر این صورت یک لیست خالی به‌اشتباه
ادعای «بازار بدون ساختار» می‌کرد.

`result.layers` نشان می‌دهد کدام لایه‌ها اجرا شده‌اند و
`result.unimplemented_layers` فهرست لایه‌هایی را می‌دهد که این نسخه درباره آن‌ها
ادعایی ندارد. برای یک تحلیل عادی این فهرست در حال حاضر **خالی** است؛ روی ورودی
نامعتبر (بدون میله یا بدون نوسان) شامل همهٔ لایه‌ها می‌شود — و همین دلیلِ ثبت
آن است. `result.detectors` می‌گوید کدام دیتکتورها اجرا، رد یا دچار خطا شدند.

لایهٔ برنامهٔ معاملاتی و لایهٔ تصمیم هر دو در pipeline اجرا می‌شوند. توجه کنید که
یک trade plan توصیهٔ معامله نیست (در JSON خودش `"is_recommendation": false` را
اعلام می‌کند) و `BUY` یعنی «از میان پلن‌هایی که از همهٔ فیلترها عبور کردند، این
یکی طبق معیارهای اعلام‌شده بیشترین شواهد را داشت» — **نه** «احتمال موفقیتش بیشتر
است». هیچ‌چیز این پروژه در برابر نتایج واقعی اعتبارسنجی نشده است.

`result.decision` یکی از `BUY` / `SELL` / `WAIT` / `NO_TRADE` به‌همراه `reason`،
توضیح مرحله‌به‌مرحله، فهرست فیلترهایی که فعال شدند و معیارهای رتبه‌بندی است.
اگر `AnalyzerConfig(enable_decision=False)` بگذارید، به‌جای تصمیم
`NO_TRADE` / `DECISION_DISABLED` می‌گیرید و ساختار و پلن‌ها همچنان گزارش می‌شوند.

**نکته مهم درباره ترتیب میله‌ها:** اندیس‌گذاری در کل کتابخانه از
**قدیمی به جدید** است؛ اندیس `0` قدیمی‌ترین میله و `len(bars) - 1`
جدیدترین میله است. این دقیقاً برعکس ترتیب سری‌های متاتریدر ۵ است و این تبدیل
فقط داخل آداپتور MT5 انجام می‌شود.

فرم‌های مجاز میله: شیء `Bar` یا دیکشنری ساده با کلیدهای `o/h/l/c`
(یا `open/high/low/close`).

## پیکربندی

تمام پارامترهای هیوریستیک قابل پیکربندی و قابل ذخیره‌سازی هستند:

```python
from albrooks import AnalyzerConfig

config = AnalyzerConfig(
    swing_k=3,
    atr_period=14,
    min_leg_bars=3,
    max_leg_bars=100,
    min_pb_ratio=0.15,
    max_pb_ratio=0.90,
)
payload = config.to_dict()          # مناسب برای JSON
restored = AnalyzerConfig.from_dict(payload)
```

بلوک `Decision Engine & Gating` (`enable_decision`، `min_score`، `min_rr`،
`max_late_atr`، `conflict_ppts`، `max_failed_attempts`) در فاز ۱ اعلام شد ولی تا
فاز ۱۵ هیچ‌جا مصرف نمی‌شد. **اکنون هر شش کلید فعال هستند** و برای هرکدام تستی
وجود دارد که نشان دهد تغییرش نتیجه را عوض می‌کند.

> `min_score` روی مقیاس **۰ تا ۱** است، همان مقیاس `EvidenceScore.value`. مقدار
> اولیه `40.0` اعلام شده بود (مقیاس ۰ تا ۱۰۰) که هر کاندیدایی، حتی کامل‌ترین را،
> رد می‌کرد. مقدار فعلی `0.40` است و با `evidence_moderate_band` هم‌خوان است.

## معیارهای رتبه‌بندی

لایهٔ تصمیم تنها جایی است که ستاپ‌ها را مقایسه می‌کند، و کل طراحی آن بر این است
که این مقایسه **قابل نقد** باشد نه قابل اتکا:

```text
(-evidence_value, -reward_to_risk, candidate_id)
```

این معیارها در `ranking_basis` خودِ خروجی تکرار می‌شوند و در
`docs/architecture/CONCEPT_TAXONOMY.md` به‌عنوان `INTERPRETATION` برچسب خورده‌اند.
`BUY` یعنی «طبق این معیارهای اعلام‌شده، بیشترین شواهد» — نه «احتمال موفقیت بیشتر».
هیچ آستانه‌ای هم کالیبره نشده است؛ تغییر `min_rr` تعداد پلن‌های واجد شرایط را
عوض می‌کند، نه کیفیتشان را.

دو چیزی که این لایه انجام **نمی‌دهد**: کم‌بدترین کاندیدا را ارتقا نمی‌دهد (اگر همه
فیلتر شوند، پاسخ `WAIT` است با ذکر فیلترهای شکست‌خورده)، و نزدیکی دو جهت را با
حساب جبر نمی‌شکند (`WAIT` / `EVIDENCE_CONFLICT`).

## چند تایم‌فریم

`albrooks.engine.pipeline` یک تایم‌فریم را تحلیل می‌کند و تصمیمش را در برابر
تایم‌فریم بالاتر می‌سنجد:

```python
from albrooks.engine.pipeline import analyze_multi_timeframe

result = analyze_multi_timeframe(
    m15_bars, h1_bars,        # Bar.time زمان *باز شدن* میله است
    ratio=4,                  # تعداد میلهٔ پایین در هر میلهٔ بالا
    symbol="EURUSD", lower_timeframe="M15", higher_timeframe="H1",
)

result.bias.direction        # ‎+1، ‎-1 یا ‎0
result.bias.reason           # HTF_ALIGNED | HTF_NOT_CLASSIFIED | HTF_NOT_ALIGNED | ...
result.alignment.warnings    # MISSING_TIMESTAMPS، TIMEFRAME_RATIO_MISMATCH، ...
```

هم‌ترازی بر اساس **زمان بسته شدن** میله انجام می‌شود، چون یک میلهٔ H1 تا وقتی
آخرین میلهٔ M15 آن بسته نشود قابل دانستن نیست. جدیدترین میلهٔ H1 قابل استفاده
در میلهٔ `i` برابر `floor((i + 1) / ratio) - 1` است — و **نه** `i // ratio`، چون
میله‌ای که در همان لحظهٔ بسته شدن یک میلهٔ بالاتر بسته می‌شود، *داخل* آن میلهٔ
بالاتر است.

سوگیری (bias) در صورت مخالفت، تصمیم را **نگه می‌دارد** و هرگز آن را معکوس
نمی‌کند؛ چون فهمیدن اینکه خرید M15 با روند نزولی H1 در تضاد است، به معنای فهمیدن
این نیست که آن خرید در واقع فروش است. با `htf_opposition_veto=False` می‌توانید
سوگیری را به‌عنوان زمینه نگه دارید بدون اینکه روی آن فیلتر شود.

## سیاست عدم بازترسیم (Non-repaint)

موتور به‌صورت پیش‌فرض **فقط روی میله‌های بسته‌شده** کار می‌کند. تشخیص‌هایی که
ذاتاً به تأیید سمت راست نیاز دارند (مانند سقف/کف فراکتالی) تنها از میله‌ای که
آن‌ها را تأیید می‌کند منتشر می‌شوند و اندیس تأیید خود را ثبت می‌کنند.

قانونی که مجموعه تست‌ها تضمین می‌کند:

> تحلیل در یک اندیس مشخص، **مستقل** از وجود یا عدم وجود میله‌های آینده یکسان است.

این وعده به‌صورت **هجده تضمین شماره‌گذاری‌شده** نوشته شده است که هرکدام نام تست
اعمال‌کننده‌اش را دارد:
`docs/algorithms/NON_REPAINT_CONTRACT.md`. یک تست آن سند را می‌خواند و اگر
تضمینی به تستی اشاره کند که وجود ندارد، شکست می‌خورد — پس قرارداد نمی‌تواند
بی‌سروصدا از کد عقب بماند.

## بک‌تست

`albrooks.backtest.events` سری را میله‌به‌میله روی میله‌های بسته‌شده طی می‌کند،
`analyze(bars, last_closed=k)` را صدا می‌زند و ثبت می‌کند که مسیر بعد از تصمیم
چه کرد:

```python
from albrooks.backtest.events import Outcome, replay

result = replay(bars, horizon=10)

result.counts()                        # نوع نتیجه -> تعداد، شامل صفرها
result.sample_share(Outcome.TARGET_FIRST)
result.mean_mfe_atr()
result.skipped                         # دلیل نبود رویداد، به تفکیک
result.caveats                         # پیش از خواندن اعداد این را بخوانید
```

پنج نوع نتیجه: `TARGET_FIRST`، `STOP_FIRST`، `NEITHER`، `AMBIGUOUS` و
`INVALID_ENTRY`. دو مورد آخر اتفاقاتی هستند که واقعاً رخ داده‌اند و به همین دلیل
پاک نمی‌شوند — میله‌ای که سقفش از هدف گذشته و کفش از حد ضرر، از OHLC قابل
ترتیب‌دهی نیست، و ورودی‌ای که از پیش از حد ضرر رسیده اصلاً معامله‌ای نبوده است.
`AMBIGUOUS` هرگز روی خود رویداد بازنویسی نمی‌شود؛ تفکیک آن در گزارش انجام
می‌شود و پیش‌فرض آن خوانش بدبینانه است.

**هیچ سود و زیانی تولید نمی‌شود.** نه منحنی سرمایه، نه امید ریاضی، نه ضریب سود،
نه نرخ برد. این‌ها همان اعدادی هستند که یک بک‌تست برای ارائه ساخته می‌شود، و هر
کدام ادعایی درباره آینده‌اند که این پروژه نمی‌تواند از آن‌ها دفاع کند: فاز ۱۹
مجموعهٔ فیکسچر طلایی را ساخت و عمداً در برابر نتایج واقعی اعتبارسنجی **نکرد**، چون
اعتبارسنجی در برابر نتایج به دادهٔ برچسب‌خوردهٔ واقعی نیاز دارد که این مخزن ندارد.
`sample_share()` نسبتی از نمونهٔ داده‌شدهٔ خودتان است و عمداً نرخ برد نامیده
نمی‌شود.

سه تنظیم که باید بدانید، چون پیش‌فرض‌ها همان‌های قابل دفاع‌اند نه آن‌های راحت:
ورود در **باز شدن میلهٔ بعد** (نخستین قیمتی که پس از تصمیم وجود داشت)، سیگنال‌های
هم‌پوشان **نادیده گرفته می‌شوند** (سه تصمیم در دوازده میله معمولاً یک روند است که
سه بار شمرده شده)، و حالت مبهم به **حد ضرر اول** تفکیک می‌شود. جزئیات در
`docs/algorithms/BACKTESTING.md`.

## فیکسچرهای طلایی

پوشهٔ `tests/fixtures/golden/` پنج نمودار دست‌ساز دارد، یکی برای هر مفهوم نام‌برده:
ورود H2، شکست محدوده، بازگشت روند، سقف دوقلوی میکرو، و فید یک حرکت اندازه‌گیری‌شده.

این‌ها **اسنپ‌شات خروجی موتور نیستند**. یک فایل طلایی که خروجی کد را ذخیره می‌کند
نمی‌تواند اصلاح را از regression تشخیص دهد — روی هر دو شکست می‌خورد، روی هیچ‌کدام
عبور نمی‌کند، و به‌روزرسانی‌اش با چسباندن جواب جدید انجام می‌شود. در عوض هر فیکسچر
مقادیر مشخصی را تثبیت می‌کند، برای هرکدام دلیلش را می‌نویسد، و فهرستی از
**مثبت‌های نقض** دارد: ویرایش‌هایی روی میله‌ها که نتیجه‌شان را مشتق پیش‌بینی می‌کند.
این‌ها ادعا دربارهٔ علّیت‌اند و اسنپ‌شات ساختاراً چنین چیزی ندارد.

سه چیزی که این مجموعه پیدا کرد، ثبت شد و به‌جای اصلاح پنهانی رها نشد:

- **چرخهٔ حیات فید از طریق پایپ‌لاین در دسترس نیست.** رجیستری فقط فید را seed
  می‌کند، پس مصرف‌کنندهٔ زنده برای projection‌ای که بازار به آن رسیده `PROJECTED` با
  `age 0` می‌بیند. اصلاحش یعنی دادن مسئولیت حالت‌دار به یک آشکارساز بی‌حالت، و این
  کارِ آداپتور است نه یک تست.
- **پنجرهٔ پولبک یک انتخاب پیکربندی است، نه خوانشی از بازار.** آشکارساز نخستین میله‌ای
  که سقف بالاتر ساخته را «پای اول» می‌نامد، پس در روند صعودی تمیز «پولبک» فقط
  `max_pb_bars` میلهٔ آخر است.
- **دو تا از سه اختلاف، اشتباه مشتق‌گیری خودمان بود**، نه نقص موتور. هر دو در
  فیکسچرها ثبت شده‌اند.

**این یک مجموعهٔ رگرسیون معنایی است، نه یک مطالعهٔ اعتبارسنجی.** مشخص می‌کند موتور
روی پنج نمودار دست‌کشیده چه چیزی را *نام‌گذاری* می‌کند. هیچ چیزی دربارهٔ کارکرد
ستاپ‌ها نمی‌گوید، و بخش ۹ از `docs/algorithms/VALIDATION.md` فهرست می‌کند برای
تغییر این وضعیت چه چیزی لازم است.

## محدودیت‌ها

- پرایس‌اکشن ال بروکس ترکیبی از هندسه عینی و قضاوت انسانی است. آنچه اینجا
  پیاده‌سازی شده **نمونه‌ای سیستماتیک (systematic proxy)** است و صراحتاً
  همین‌طور برچسب‌گذاری شده. هیچ بخشی از این مخزن ادعا نمی‌کند که «دقیقاً
  همان چیزی است که ال بروکس منظور کرده».
- **هیچ ادعای سودآوری، دقت یا نرخ برد** وجود ندارد و تاکنون هیچ‌کدام
  به‌صورت آماری اعتبارسنجی نشده‌اند.
- بافت بازار، طبقه‌بندی روند و «کیفیت» H2 همگی هیوریستیک هستند.
- امتیازهای خروجی، وزن شواهد (evidence weights) هستند نه احتمال.
- این نرم‌افزار یک سیستم معاملاتی نیست و داده عملکردی معاملاتی ارائه نمی‌دهد.
